# Shared core / 公共核心

Canonical editable shared sources. [source-map.json](source-map.json)
declares the generated native outputs, not a second implementation.

| Directory | Ownership |
| --- | --- |
| design/ | Shared popup, taskbar icon canvas, panel, clock flyout, lock-screen and generic WinUI control geometry/metrics |
| palette/ | Color classification, fixed roles, ICC/automatic accent and scheme template |
| materials/ | Window material and popup frame generation |
| transactions/ | Shared user-owned file validation, atomic replacement and rollback |
| controls/ | Shared glyphs, buttons, avatars, sliders, scrollbars, flyout controls and palette tokens |
| resources/ | Shared portrait/license and original resource import/validation |
| animations/ | Shared sign-in progress |
| logic/ | Shared formatting, battery state, lock-screen text and optional panel capability lookup |

Common QML/JS files retain their native filenames and relative imports.
Python tools are edited here and executed via their existing native
script paths. Source-only aliases preserve those paths without duplicate
implementations. The file transaction module is copied into the installed
appearance package and does not own the caller's writer lock or renderer
plan. Do not create separate light/dark functionality.
The Digital Clock package consumes shared `FlyoutButton.qml` and `Win11Palette.qml` from this directory; Calendar and Notifications do not maintain separate copies. Their native package paths remain unchanged through `source-map.json`. Its card and button geometry is centralized in `design/clockMetrics.js`; colors remain in `Win11Palette.qml`.
The greeter and lock-screen packages also consume shared `AccountAvatar.qml` and `VirtualKeyboardButton.qml`; host-specific presentation is configured without maintaining feature-local implementations.
Quick Settings uses `design/panel/trayMetrics.js` for the shared normal/split tile geometry, caption line budget, slider row and glyph dimensions, detail-page action button height, row outer inset, content inset, row spacing and leading icon extent, and the panel/footer/media horizontal inset. Login and LockScreen share the avatar maximum, clock metrics (including line spacing) and credential dim opacity through `design/lockMetrics.js`, while retaining the host-specific viewport clamps and field dimensions. Their power menus share padding and overlay radius there; login and lock-screen widths remain separately named until native 26H2 layout evidence confirms a common value. Generic `ControlCornerRadius`, `OverlayCornerRadius`, taskbar Search box radius and Start/Search micro-interaction duration are owned by `design/controlMetrics.js` and consumed by Digital Clock, Start/Search list and action controls (including power-menu options), Quick Settings detail rows, Clipboard history items, System Tray hover controls, RunDialog, taskbar preview controls, standalone Search and Login/LockScreen controls. Taskbar window-preview hover surfaces use the separate `cardSurfaceRadius` token. Start/Search/Alt+Tab, Quick Settings media cards and notification message cards share a separate `cardSurfaceRadius` token; it remains distinct from the overlay radius. `MenuFlyoutThemeMinHeight` is shared by Start context/view menus and the lock-screen menu item. Login and LockScreen also share sign-in button radius and power-menu geometry through `design/lockMetrics.js`. Host-specific layout remains in the owning modules.
Equal numeric values alone do not establish equal semantic roles.

Run `python3 -I scripts/materialize-modules.py --prepare` to generate
the ignored native files and validate source-only aliases. The equivalent
`--write` is retained for compatibility. `--check` compares generated bytes,
executable modes and alias targets without writing.
The taskbar layout uses one shared body. The mapped Aurorae and Kvantum
source templates, color-scheme template and selected frame tools now
have generated-only native paths. The renderer-specific appearance
materializer prepares these inputs and generates the actual packages.
Window-frame regeneration without an explicit staged directory writes
modules/windowmanager/decoration/decoration.svg, the editable owner.
The Plasma SVG atlas is owned by platform/plasma/appearance/atlas;
its native tree is generated from the source map. Popup and panel frame
generators write that atlas by default. The installable icon theme remains
owned by icons/windows-modern; its exact duplicate SVG names are governed by
the [canonical alias manifest](../icons/windows-modern-aliases.json) and
[SVG resource policy](../docs/SVG_RESOURCES.md). Wallpaper assets retain
their existing package ownership.
